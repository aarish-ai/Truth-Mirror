# Truth Mirror — Comprehensive Codebase Analysis

> **Scope**: Every Python module (57 files), the frontend, Docker config, and tests.
> **Goal**: Identify all bugs, logic errors, inefficiencies, security issues, and improvement opportunities.

---

## Project Understanding

Truth Mirror is a **geopolitical claim verification engine** that:
1. Accepts a natural-language claim via a web UI or API
2. Decomposes it into sub-claims
3. Retrieves evidence from 15+ sources (news, academic, fact-checkers, archives, non-Western media)
4. Analyzes source credibility, stance, and geopolitical perspective
5. Triangulates across ideologically opposing sources
6. Produces a verdict with confidence score, hidden narratives, and perspective divergence analysis

The architecture flows: `app.py` → `orchestrator.py` / `geo_orchestrator.py` → decomposition → retrieval → analysis → verdict.

### C1. Geo-Credibility Overrides Are Completely Ignored
**File**: [credibility.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/credibility.py) + [credibility_registry.json](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/credibility_registry.json)

**Problem**: `credibility_registry.json` defines `geo_credibility_overrides` with bias adjustments for state media (TASS, RT, CGTN, etc.). However, `CredibilityRegistry.load()` in `credibility.py` **never reads or applies this key**. All geopolitical credibility overrides silently fall back to the default `0.55` score, completely neutralizing the bias-adjustment engine — a core feature of the project.

**Fix**: Parse `geo_credibility_overrides` in `CredibilityRegistry.load()` and apply them during credibility scoring when a geopolitical context is detected.

### C2. SPARQL Injection in Knowledge Graph Verifier
**File**: [kg_verifier.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/kg_verifier.py)

**Problem**: `entity_name` is injected directly into `build_sparql_query` without escaping double quotes. A claim containing `"` characters can break SPARQL syntax or alter the query semantics.

### C3. aiohttp Session Created Per Request (Socket Exhaustion)
**File**: [source_analyzer.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/source_analyzer.py)

**Problem**: `aiohttp.ClientSession()` is instantiated independently on **every single async API call** to Gemini and OpenRouter. This bypasses connection pooling entirely, causes massive TCP overhead, and leads to socket exhaustion under any meaningful load.

**Fix**: Create a single `aiohttp.ClientSession` per pipeline run (or use a shared session with connection pooling) and pass it through or store it as an instance attribute.

### C4. Missing `timeout` on ALL Network Calls in Retrieval Modules
**Files**: [retrieval_fact.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/retrieval_fact.py), [retrieval_archival.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/retrieval_archival.py), [retrieval_quotes.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/retrieval_quotes.py)

**Problem**: Multiple `requests.get()` calls across Snopes, GovInfo, Wikidata, WorldBank, Wayback Machine, OpenLibrary, and Wikiquote have **no `timeout` parameter**. Any of these can hang indefinitely and stall the entire pipeline.

**Fix**: Add `timeout=15` (or configurable) to every `requests.get()` and `requests.post()` call.

### C5. XML External Entity (XXE) Vulnerability in RSS Parsing
**File**: [retrieval_news.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/retrieval_news.py)

**Problem**: Uses native `xml.etree.ElementTree.fromstring()` to parse untrusted RSS feeds from the internet. This is vulnerable to XXE attacks that could read local files or trigger SSRF.

**Fix**: Replace with `defusedxml.ElementTree.fromstring()` from the `defusedxml` package.

### C6. Zero-Vector Embeddings Silently Poison Similarity Search
**File**: [embeddings.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/embeddings.py)

**Problem**: When the Gemini embedding API fails, the fallback returns `[0.0] * 768`. These zero vectors have zero cosine similarity with everything, but in FAISS (L2 distance), they'll match at predictable distances, silently injecting garbage results into the ranking pipeline.

**Fix**: Return `None` on failure and handle the `None` case in callers by skipping those items rather than storing toxic embeddings.

### C11. Race Condition in Thread Pool Destroys Result Ordering
**File**: [search_planner.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/search_planner.py)

**Problem**: Results are appended to `all_results` via `as_completed(futures)`. This returns results in the order threads finish, not in relevance order. Search engines return ranked results, but this approach randomizes that ranking.

### C12. `rt.com` Domain Matching Catches `art.com`, `smart.com`
**File**: [triangulation.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/triangulation.py)

### C13. `"time"` Fuzzy-Matches `"new york times"` in Source Registry
**File**: [source_registry.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/source_registry.py)

**Problem**: The fallback logic `if known_name in pub_lower or pub_lower in known_name:` means a publisher named `"time"` matches `"new york times"` (and vice versa), incorrectly assigning the wrong credibility and bias metadata.

**Fix**: Use exact matching first, then use token-set similarity (e.g., Jaccard over words) instead of substring containment.

### C14. `_call_count` Thread Safety Issue
**File**: [gemini_analyzer.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/gemini_analyzer.py)

**Problem**: `GeminiAnalyzer._call_count` is a class-level counter incremented without locks. In a threaded environment (the server uses `ThreadingHTTPServer`), concurrent requests can cause race conditions on this counter, either exceeding or under-counting API calls.

**Fix**: Use `threading.Lock()` around counter increments or switch to `threading.atomic` / `itertools.count`.

### H6. Gemini Safety Filter Causes Unhandled Crash

### H8. Substring Matching Causes False Positive Keyword Skips
**Files**: [retrieval_news.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/retrieval_news.py), [retrieval_acad.py](file:///c:/Users/DELL/.gemini/antigravity/scratch/Truth%20Mirror/truth_mirror/retrieval_acad.py)

**Fix**: Use regex word boundaries: `re.search(rf'\b{re.escape(term)}\b', text)`.

## Architecture-Level Recommendations

### A1. Create a Shared LLM Client Layer
The codebase has **5+ different ways** of calling LLMs (direct Groq SDK, Gemini HTTP, Gemini SDK, OpenRouter via requests, OpenRouter via urllib, OpenRouter via OpenAI SDK). Consolidate into a single `LLMClient` with provider-agnostic methods and built-in JSON parsing, markdown stripping, retry logic, and rate limiting.

### A2. Unify Caching Strategy
There are **3 separate caching mechanisms**: SQLite (`caching.py`), JSON file (`retrieval.py`), and in-memory dicts. Consolidate on the SQLite cache with proper TTL and cleanup.

### A3. Implement Structured Logging
Replace all `print()` statements with Python's `logging` module. Add request IDs for tracing through the pipeline.

### A4. Add Integration Test Assertions
`test_integration.py` is a manual smoke test with no assertions. Add proper `assert` statements and run it in CI.

### A5. Split the Frontend
`static/index.html` is a 1600-line monolith. Split into separate HTML, CSS, and JS files for maintainability.

### A6. Fix Import Style for Deployment
Multiple files use `from truth_mirror.module import X` which breaks when running from within the `truth_mirror/` directory (per deployment rules). Switch to relative imports: `from .module import X`.
